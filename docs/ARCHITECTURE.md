## 设计目标

第一版采用单体模块化架构，优先保证个人学习环境中的可理解性、可运行性和业务链完整性。前端与后端通过 REST API 解耦，后端根包为 `cn.zhuatech.erp`，MySQL 表统一使用 `erp_` 前缀。

## 分层

- `controller`：HTTP 边界、参数校验、角色约束和响应封装。
- `service`：订单建档、库存变动、财务核销等事务与业务规则。
- `repository`：Spring Data JPA 数据访问和经营指标聚合。
- `model`：商品、商业伙伴、销售、采购、库存、财务和账号领域实体。
- `security`：JWT 签发、认证过滤和无状态安全配置。
- `dto`：输入输出模型，不直接暴露持久化实体。

## 关键业务约束

1. 客户只能用于销售订单，供应商只能用于采购订单。
2. 出库后库存不得小于零；每次库存变化记录变动前、变动后数量和来源单号。
3. 销售订单已收金额不得超过订单总额。
4. 财务核销金额不得小于零或超过应结金额，状态自动计算为待处理、部分核销或已结清。
5. 商品、商业伙伴等主数据由管理员或经营管理角色维护；销售、采购、财务和仓库角色按职责写入业务数据。

## 数据流

```text
Vue H5 -> Nginx -> Spring Security/JWT -> Controller -> ErpService -> JPA -> MySQL
```

Flyway 在应用启动时验证并执行数据库迁移。`DataInitializer` 只在用户表为空时写入演示数据，避免重复初始化。

## 当前边界

第一版订单以“商品摘要 + 商品种类数”表达订单内容，适合快速学习和产品验证。正式的商业项目通常还需要订单明细行、税率、折扣、批次、多仓库、多币种、会计期间、审计日志和细粒度数据权限，这些能力应根据取得的商业授权和实际业务蓝图继续实现。
